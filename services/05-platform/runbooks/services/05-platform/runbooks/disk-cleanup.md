# Runbook: Оперативне очищення дискового простору серверів Платформи

**Сервіс:** `05-platform`  
**Роль відповідального:** Incident Manager / Risk & Knowledge Manager / Системний адміністратор  
**Призначення:** Покрокова інструкція для інженерного складу з виявлення, локалізації та безпечного усунення критичного заповнення дискових накопичувачів (P1 / P3).  
**Шлях у репозиторії:** `services/05-platform/runbooks/disk-cleanup.md`

---

## 1. Симптоми та тригери

Інструкція застосовується при виконанні одного з тригерів:

- **P3 (Warning):** Сповіщення моніторингу про заповнення дискового простору понад **80%**.
- **P1 (Critical):** Заповнення диска понад **90%** або поява помилок запису в СУБД / зупинка реплікації (аналог інциденту `#16`).

---

## 2. Діагностика (аналіз джерела заповнення)

Виконайте послідовно команди в терміналі сервера платформи.

### 2.1. Перевірка загального стану файлових систем

```bash
df -h /
```

### 2.2. Визначення найбільших директорій та файлів

```bash
sudo du -ahx / 2>/dev/null | sort -rh | head -n 10
```

### 2.3. Аналіз логів та тимчасових файлів

```bash
sudo ncdu /var/log /tmp
```

---

## 3. Покроковий план очищення

### Крок 1: Видалення застарілих ротованих логів

Видаліть стиснуті архівні логи (`*.gz`, `*.1`, `*.old`), які старші за 7 днів:

```bash
sudo find /var/log -type f \( -name "*.gz" -o -name "*.1" -o -name "*.old" \) -mtime +7 -delete
```

### Крок 2: Безпечне очищення тимчасових дампів та файлів

Видаліть застарілі дамп-файли СУБД та тимчасові кеші з директорії `/tmp/`:

```bash
sudo find /tmp -type f -name "*.sql" -mtime +1 -delete
sudo find /tmp -type f -name "*.sql.gz" -mtime +1 -delete
sudo find /tmp -type f -name "*.tmp" -mtime +1 -delete
```

### Крок 3: Примусовий запуск ротації активних логів

Виконайте позапланову ротацію поточних логів за допомогою конфігуратора `logrotate`:

```bash
sudo logrotate -f /etc/logrotate.d/platform-logs
```

---

## 4. Перевірка та верифікація

### 4.1. Перевірка залишку вільного місця

```bash
df -h /
```

Цільовий показник після очищення — заповненість не більше **40–50%**.

### 4.2. Перевірка статусу робочих служб платформи

```bash
sudo systemctl status postgresql
sudo systemctl status prometheus-node-exporter
```

### 4.3. Оновлення статусу в тикеті GitHub

Укажіть актуальний відсоток вільного місця та передайте інформацію Incident Manager для закриття інциденту.

---

## 5. Профілактика та запобігання повторним аваріям

Для уникнення повторного виникнення P1-інцидентів:

- Перевірте наявність конфігурації `logrotate`.
- Переконайтеся, що файл `/etc/logrotate.d/platform-logs` містить наступні параметри:

```text
/var/log/platform/*.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
```
