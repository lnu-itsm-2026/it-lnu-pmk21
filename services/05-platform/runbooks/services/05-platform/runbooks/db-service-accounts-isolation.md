# Runbook: Налаштування та обслуговування ізольованих сервісних акаунтів БД (`svc_export_ro`)

* **Сервіс:** 05 Платформа (БД, Backup, Monitoring)
* **Пов'язані інциденти та проблеми:** `#100`, `#102`, `#103`, `#104`, `#113`, `#120`
* **Власник процедури:** Service Owner (`service:05`)

## 1. Призначення
Процедура визначає правила створення, обмеження доступу та ротації секретів для сервісних облікових записів бази даних, які використовуються для регламентних вивантажень (зокрема нічного експорту о `01:00` із `export-01` для звітів Moodle).

## 2. Вимоги безпеки до сервісних акаунтів БД
1. **Принцип найменших привілеїв:** обліковий запис має лише право `SELECT` на вичерпний перелік таблиць/представлень, необхідних для конкретного завдання (без доступу до інших таблиць персональних і фінансових даних).
2. **Мережева ізоляція:** підключення до БД дозволено виключно з IP-адреси сервера-клієнта (`export-01`). Інтерактивний вхід по SSH на сервери БД для сервісних акаунтів заборонено (`/sbin/nologin`, відсутність `~/.ssh/authorized_keys`).
3. **Захист секретів:** зберігання паролів або ключів відкритим текстом у скриптах на спільному Диску чи в загальних директоріях заборонено. Секрет зберігається лише в локальному конфігураційному файлі на `export-01` із правами `chmod 600`.
4. **Ротація:** обов'язкова планова зміна пароля сервісного акаунта раз на 90 днів або негайно у разі підозри на компрометацію.

## 3. Порядок налаштування та перевірки
1. Створити на репліці БД `db-replica-2` (`10.20.5.12`) обліковий запис `svc_export_ro` із правами лише `SELECT` на потрібні таблиці та обмеженням хоста підключення IP-адресою `export-01`.
2. Зберегти згенерований пароль у захищений файл конфігурації на `export-01` (`/etc/platform/db-export.env`, власник `root:platform`, права `chmod 600`).
3. Прописати шлях до конфігураційного файлу в налаштуваннях нічного завдання експорту (`01:00`) та регламентних скриптів Платформи.
4. Виконати контрольний тестовий запуск експорту та підтвердити з Командою 03 (`service:03`), що дані у звітах Moodle оновилися коректно.

## 4. Дії у разі компрометації сервісного акаунта
1. Негайно заблокувати скомпрометований обліковий запис у БД та ОС (`/sbin/nologin`, видалення ключів).
2. Перевірити активні з'єднання та журнал аудиту БД на наявність нетипових вивантажень.
3. Створити новий обліковий запис із новим паролем за розділом 3 цього runbook'а, оновити конфігурацію на `export-01` та запустити позаплановий експорт для відновлення актуальності звітів Moodle.
